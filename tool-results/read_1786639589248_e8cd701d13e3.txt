     1→PRD — AI HTML Workspace Editor
     2→
     3→1. Product Overview
     4→
     5→Build a polished browser-based AI HTML Workspace Editor for creating, editing, previewing, testing, and downloading multi-file static websites through an AI coding agent.
     6→
     7→The product combines:
     8→
     9→- AI coding agent
    10→- Multi-file HTML/CSS/JS editor
    11→- Live website preview
    12→- Browser automation/testing
    13→- Console and error inspection
    14→- AI reasoning/thinking panel
    15→- Collapsible tool-call cards
    16→- Chat history
    17→- Workspace management
    18→- OpenAI-compatible API configuration
    19→- ZIP workspace export
    20→
    21→The application should feel like a modern developer tool rather than a basic HTML playground.
    22→
    23→The primary desktop experience uses a three-zone layout:
    24→
    25→┌──────────────────────────────────────────────────────────────────────────┐
    26→│ Sidebar │                 Workspace Header                               │
    27→│         ├────────────────────────────────────┬───────────────────────────┤
    28→│         │                                    │                           │
    29→│         │       Editor / Preview Area        │        AI Chat             │
    30→│         │                                    │                           │
    31→│         │                                    │                           │
    32→│         │                                    │                           │
    33→│         │                                    │                           │
    34→│         ├────────────────────────────────────┤                           │
    35→│         │ Editor / Preview Controls          │        Prompt Box          │
    36→└─────────┴────────────────────────────────────┴───────────────────────────┘
    37→
    38→The interface must have clear visual hierarchy and avoid overcrowding.
    39→

    42→2. Design Direction
    43→
    44→Visual style
    45→
    46→Use a modern developer-tool aesthetic:
    47→
    48→- Rounded cards
    49→- Subtle borders
    50→- Moderate corner radius
    51→- Clean typography
    52→- Compact controls
    53→- Smooth transitions
    54→- Minimal shadows
    55→- Strong spacing hierarchy
    56→- Dark and light appearance support
    57→- Responsive behavior
    58→- Keyboard accessibility
    59→
    60→Do not make every element look like a floating card. Panels should primarily use borders and background separation.

    63→
    64→Use three visual levels:

    66→Level 1 — Application surfaces
    67→
    68→Large areas such as:
    69→
    70→- Sidebar
    71→- Editor
    72→- Preview
    73→- Chat
    74→
    75→Use subtle background differences and borders.
    76→
    77→Level 2 — Interactive containers
    78→
    79→Examples:
    80→
    81→- File explorer
    82→- Chat messages
    83→- Thinking panel
    84→- Tool cards
    85→- Prompt box
    86→- Settings sections
    87→
    88→Use rounded corners and subtle borders.
    89→

    91→
    92→Examples:
    93→
    94→- Buttons
    95→- Tabs
    96→- Dropdowns
    97→- Icon buttons
