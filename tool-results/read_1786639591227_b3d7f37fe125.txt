     1→     1→PRD — AI HTML Workspace Editor
     2→     2→
     3→     3→1. Product Overview
     4→     4→
     5→     5→Build a polished browser-based AI HTML Workspace Editor for creating, editing, previewing, testing, and downloading multi-file static websites through an AI coding agent.
     6→     6→
     7→     7→The product combines:
     8→     8→
     9→     9→- AI coding agent
    10→    10→- Multi-file HTML/CSS/JS editor
    11→    11→- Live website preview
    12→    12→- Browser automation/testing
    13→    13→- Console and error inspection
    14→    14→- AI reasoning/thinking panel
    15→    15→- Collapsible tool-call cards
    16→    16→- Chat history
    17→    17→- Workspace management
    18→    18→- OpenAI-compatible API configuration
    19→    19→- ZIP workspace export
    20→    20→
    21→    21→The application should feel like a modern developer tool rather than a basic HTML playground.
    22→    22→
    23→    23→The primary desktop experience uses a three-zone layout:
    24→    24→
    25→    25→┌──────────────────────────────────────────────────────────────────────────┐
    26→    26→│ Sidebar │                 Workspace Header                               │
    27→    27→│         ├────────────────────────────────────┬───────────────────────────┤
    28→    28→│         │                                    │                           │
    29→    29→│         │       Editor / Preview Area        │        AI Chat             │
    30→    30→│         │                                    │                           │
    31→    31→│         │                                    │                           │
    32→    32→│         │                                    │                           │
    33→    33→│         │                                    │                           │
    34→    34→│         ├────────────────────────────────────┤                           │
    35→    35→│         │ Editor / Preview Controls          │        Prompt Box          │
    36→    36→└─────────┴────────────────────────────────────┴───────────────────────────┘
    37→    37→
    38→    38→The interface must have clear visual hierarchy and avoid overcrowding.
    39→    39→

    42→    42→2. Design Direction
    43→    43→
    44→    44→Visual style
    45→    45→
    46→    46→Use a modern developer-tool aesthetic:
    47→    47→
    48→    48→- Rounded cards
    49→    49→- Subtle borders
    50→    50→- Moderate corner radius
    51→    51→- Clean typography
    52→    52→- Compact controls
    53→    53→- Smooth transitions
    54→    54→- Minimal shadows
    55→    55→- Strong spacing hierarchy
    56→    56→- Dark and light appearance support
    57→    57→- Responsive behavior
    58→    58→- Keyboard accessibility
    59→    59→
    60→    60→Do not make every element look like a floating card. Panels should primarily use borders and background separation.
    61→    61→
    62→    62→Component hierarchy
    63→    63→
    64→    64→Use three visual levels:
    65→    65→

    67→    67→

    69→    69→
    70→    70→- Sidebar
    71→    71→- Editor
    72→    72→- Preview
    73→    73→- Chat

    75→    75→Use subtle background differences and borders.
    76→    76→
    77→    77→Level 2 — Interactive containers
    78→    78→
    79→    79→Examples:
    80→    80→
    81→    81→- File explorer

    85→    85→- Prompt box

    87→    87→

    91→    91→
